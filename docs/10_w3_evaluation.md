# 知客 ZhiKe AI：W3 Agent 评测标准

## 1. 评测目标

W3 评测关注知客是否将 W2 的 Skills 工作流整合为可交付、可交互的业务 Agent。评测不仅检查文本输出，还检查业务目标、跟进反馈、KPI 更新和行动建议之间是否形成可信闭环。

评测对象是当前网页 Agent Demo，不将真实 CRM、数据库、企业权限或外部系统接入作为本阶段必备能力。

## 2. 总体评分体系（100 分）

| 维度 | 权重 | 核心问题 |
|---|---:|---|
| 客户处理 Skills 完整性 | 20 | 能否从输入稳定生成档案、分析、判断、建议、话术和日报？ |
| 事实边界与业务审慎性 | 15 | 是否区分事实、推断、未知，避免虚构预算、业绩或承诺？ |
| Agent 交互闭环 | 15 | 是否支持目标设定、报告生成、反馈记录与结果更新？ |
| KPI 计算可追溯性 | 20 | KPI 是否只由业务员确认的事件更新，并可解释来源？ |
| 行动建议与目标联动 | 15 | 是否能将客户优先级、风险和目标缺口转化为具体行动？ |
| 运行稳定性与容错 | 10 | Mock/API 模式下是否能完成核心演示，异常是否不破坏报告链？ |
| 界面可理解性 | 5 | 非技术业务员能否理解输入、输出、反馈和数据范围？ |

## 3. 各维度的测试方法与合格标准

### 3.1 客户处理 Skills 完整性（20 分）

- **测试输入：** 使用 `docs/04_demo_case.md` 的三个案例，或同等复杂度的客户纪要。
- **评价方式：** 检查 7 个输出标签页是否可显示；抽查客户信息、需求、机会、跟进和话术之间是否前后一致。
- **合格标准：** 三个案例均能输出完整报告；关键字段缺失时标记“未知/待确认”，不因缺一字段而中断整份报告。

### 3.2 事实边界与业务审慎性（15 分）

- **测试输入：** 含预算未知、决策人未知或时点不明确的客户记录。
- **评价方式：** 检查模型是否将未知内容标注为待确认，是否对机会等级说明依据和风险。
- **合格标准：** 不把未出现的预算、决策权限、成交概率或效果承诺写为事实。

### 3.3 Agent 交互闭环（15 分）

- **测试步骤：** 设置业务目标 → 生成客户报告 → 打开 KPI 与行动页 → 记录一条反馈。
- **评价方式：** 检查用户操作是否顺畅，反馈后是否在同一会话中保留状态。
- **合格标准：** 目标、客户、反馈和 KPI 页面可连贯完成；无须修改代码或手工编辑数据文件。

### 3.4 KPI 计算可追溯性（20 分）

- **测试步骤：** 先生成报告，不记录反馈；随后分别记录“有效沟通”“需求确认”“方案沟通/演示”。
- **评价方式：** 对照每次反馈前后的指标数值和反馈记录。
- **合格标准：** 仅生成报告时 KPI 不增加；每个确认事件只改变对应指标；重复生成同一客户不重复计数；外部模型不可用时 KPI 计算仍可验证。

### 3.5 行动建议与目标联动（15 分）

- **测试输入：** 至少生成两条客户记录，并设置有缺口的目标。
- **评价方式：** 检查“今日优先行动”和“节奏与风险提醒”是否包含客户、优先级、下一步和风险说明。
- **合格标准：** 行动队列可对应具体客户；建议不是“继续跟进”式空话；风险提示不将 AI 推断误写为既成事实。

### 3.6 运行稳定性与容错（10 分）

- **测试步骤：** 分别在 Mock 模式与已配置 API 的模式下进行一次报告生成；模拟缺失信息输入。
- **评价方式：** 记录是否能完成核心路径、是否有可理解的错误提示。
- **合格标准：** Mock 模式能完整演示；模型输出不完整时不应使整个报告不可用；KPI 事件处理不影响已有报告。

### 3.7 界面可理解性（5 分）

- **测试对象：** 未参与开发的测试者或交叉评测者。
- **评价方式：** 观察其是否能在无口头指导下找到输入区、生成按钮、KPI 页和反馈表单。
- **合格标准：** 能在 3 分钟内完成一次“输入—报告—反馈—查看 KPI”的主流程，并理解会话数据不持久化的提示。

## 4. 建议测试矩阵

| 场景 | 关键操作 | 预期验证 |
|---|---|---|
| 企业培训客户 | 生成报告，确认有效沟通与演示 | B2B 需求分析、机会判断、演示 KPI 更新 |
| 课程顾问客户 | 生成报告，确认需求 | 高频咨询场景、信息缺口、合格客户判断 |
| 企业服务客户 | 生成报告，记录补充材料需求 | 数据保密风险、行动队列与风险提醒 |
| 重复生成同一客户 | 连续点击生成报告 | 客户不重复计数，KPI 保持不变 |
| 无 API 模式 | 开启强制 Mock | Skills 与 KPI 主流程可运行 |

## 5. 自动与人工检查

项目提供两组基础回归测试：

- `tests/test_workflow.py`：检查七步 Skills 调度、单步异常回退和完整执行轨迹；
- `tests/test_kpi_agent.py`：检查 KPI 状态层的关键不变量：

1. 重复输入同一客户不会生成重复客户记录；
2. KPI 初始值不会因“生成报告”而虚增；
3. 只有确认的反馈事件才改变对应 KPI。

人工评测负责判断业务分析是否合理、话术是否可用、交互是否易理解。自动测试不能替代业务判断。

## 6. 评测边界

W3 不评测真实数据库准确性、跨会话客户记忆、多用户权限、真实 CRM/微信/日历连接或企业级安全部署。这些属于后续产品阶段。当前评测以“可运行 Agent 是否展示真实交互与用户价值”为边界。

## 7. 当前测试证据与结果记录

项目将“评测标准”和“已实际完成的测试”分开记录，避免把目标值表述为已达成结果：

- 基础回归测试、页面冒烟测试及其结论见 `docs/11_w3_test_evidence.md`；
- 三个内置案例已完成云端 MiniMax API 复验，具体运行记录见 `docs/11_w3_test_evidence.md`；非开发者易用性测试可作为后续补充证据；
- API 异常时的本地回退仅用于保证核心链路可演示，不替代真实模型模式验收。

## 8. 总结

知客 W3 的评测重点是：AI 是否能在清晰边界下把客户处理 Skills、业务员确认的反馈和可追溯 KPI 行动闭环结合起来。高分不取决于输出篇幅，而取决于可运行性、业务审慎性、计数可信度和下一步行动的可执行性。
