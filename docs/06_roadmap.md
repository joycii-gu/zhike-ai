# 知客 ZhiKe AI：产品路线图（Roadmap）

> 项目定位：面向业务员的 AI 业务处理智能体  
> 适用阶段：S3 全球青年培育赛 · W2 复赛 · X创新赛道  
> 路线图原则：当前能力以实际 Demo 验收为准，未来能力均作为规划项

## 1. 路线图说明

知客 ZhiKe AI 当前以 W2 Prototype 验证核心业务处理闭环：将客户信息和沟通记录转化为客户档案、需求分析、业务机会判断、跟进建议、沟通话术和业务日报。W2 的重点是证明结构化 Workflow 是否可运行、输出是否可评测，而不是一次性建设完整商业系统。

后续路线图将围绕以下方向逐步演进：

- 业务流程自动化；
- 真实多客户管理能力；
- 连续性的 Agent 记忆与业务辅助；
- 外部业务系统连接；
- 企业级权限、安全和部署能力。

长期方向是从单次网页 Demo 逐步发展为可部署的 AI Business Employee 系统。当前及未来的核心目标都不是替代业务员，而是增强业务员理解客户、处理信息、判断风险和制定行动计划的能力。关键沟通、报价和业务决策仍由人工确认。

## 2. W2：核心业务闭环验证阶段

### 2.1 阶段目标

通过可运行网页 Demo 验证以下核心闭环：

**客户信息输入 → 客户档案生成 → 客户需求分析 → 业务机会判断 → 跟进建议 → 沟通话术 → 业务日报**

本节列出的能力属于 W2 Prototype 的提交范围。是否已完成应以实际代码、可运行页面、演示记录和评测结果为准；路线图或设计文档本身不作为实现证明。

### 2.2 产品能力

- 网页 Demo；
- 客户信息输入；
- 客户档案生成；
- 客户需求分析；
- 业务机会判断；
- 跟进建议生成；
- 沟通话术生成；
- 业务日报生成；
- 至少 3 个示例案例；
- 基于实际输出的示例评测结果。

### 2.3 技术能力

- 多步骤 Skills Workflow；
- 结构化字段输出；
- “事实/推断/未知”信息边界；
- 上下文剪裁与必要证据传递；
- 后端内存 Mock 客户数据模拟跨客户日报；
- 100 分制基础评测体系。

### 2.4 W2 Mock 日报边界

W2 后端内存预置 2—3 个 Mock 今日客户，用于与当前输入客户联合验证跨客户汇总、优先级排序、待办合并和全局风险提醒。Mock 数据不写入数据库，不进行跨会话持久化；页面刷新或服务重启后恢复初始状态。该机制不等同于真实多客户管理。

### 2.5 当前限制

W2 不包含：

- 登录注册；
- 数据库存储；
- 跨会话持久化；
- 长期客户记忆；
- 真实 CRM 接入；
- 微信自动读取；
- 名片 OCR；
- 日历自动同步；
- 多用户权限；
- 付费系统；
- 企业级部署。

## 3. W3：业务 Agent 能力增强阶段

W3 的目标是将单次业务处理 Demo 升级为具备连续业务辅助能力的 Agent。以下内容均为下一阶段规划，尚不属于 W2 已实现能力。

### 3.1 多客户管理

#### 规划能力

- 客户列表；
- 客户状态管理；
- 客户优先级排序；
- 跟进记录保存；
- 客户筛选和基础检索。

#### 用户价值

帮助业务员持续管理多个真实客户，而不再局限于单次输入和 Mock 客户汇总。

#### 验证重点

- 客户数据是否正确保存和读取；
- 状态变化与优先级是否一致；
- 跟进记录是否可回溯；
- 不同客户之间是否发生信息串扰。

### 3.2 Agent 长期记忆

#### 规划能力

- 保存客户历史沟通；
- 记录业务员跟进过程；
- 识别客户需求和阶段变化；
- 基于历史信息提供连续性建议；
- 支持记忆修正和删除。

#### 用户价值

让 AI 从一次性处理助手逐步转变为具有上下文连续性的业务伙伴，减少重复输入和人工回忆成本。

#### 验证重点

- 记忆是否准确；
- 新旧信息冲突时能否正确更新；
- 被删除或修正的信息是否继续影响输出；
- 历史信息是否被错误关联到其他客户。

### 3.3 个性化业务策略

#### 规划能力

根据以下信息生成更有针对性的跟进方案：

- 行业；
- 客户类型；
- 经验证的历史成功案例；
- 业务员工作习惯；
- 团队既定业务规则。

#### 用户价值

在保持事实边界和人工确认的前提下，提高建议与行业、客户阶段和业务员工作方式的匹配度。

#### 实施边界

个性化不等于自动复制历史做法。历史案例应经过脱敏和质量筛选，个性化建议仍需业务员确认。

### 3.4 更多业务场景 Skills

规划新增：

- 邮件整理；
- 会议纪要；
- 商机分析；
- 销售复盘；
- 周报生成。

新增 Skill 应继续遵循明确输入、结构化输出、事实边界、合格标准和独立评测原则，避免重新退化为一个超长 Prompt。

## 4. W4：企业级 AI 业务员工阶段

W4 的目标是探索将个人业务助手升级为企业可部署的 AI 业务员工。以下能力属于长期产品方向，需要在接口、权限、合规、安全和真实业务试点完成验证后才能交付。

### 4.1 外部系统连接

#### 规划接入

- CRM；
- 微信或经授权的企业通讯工具；
- 日历；
- 邮件系统；
- 名片 OCR。

#### 用户价值

在获得明确授权并满足数据合规要求的前提下，让 AI 进入真实业务流程，减少手工复制和跨系统整理工作。

#### 前置条件

- 接口可用且授权清晰；
- 最小权限访问；
- 数据传输和存储边界明确；
- 操作日志可审计；
- 高风险动作保留人工确认。

### 4.2 多角色业务 Agent

根据不同岗位职责，规划形成差异化的业务 Agent。不同角色应共享统一的权限、安全和事实边界基础，但使用独立的工作流、输出 Schema 与评测标准。

#### 销售 Agent

负责：

- 客户分析；
- 机会判断；
- 跟进建议；
- 销售日报。

#### 客服 Agent

负责：

- 客户问题整理；
- 回复建议；
- 服务记录；
- 风险升级提醒。

#### 企业顾问 Agent

负责：

- 需求分析；
- 方案准备；
- 商务沟通重点；
- 项目跟进建议。

### 4.3 企业级部署能力

规划能力包括：

- 权限管理；
- 团队空间；
- 企业知识库；
- 数据安全机制；
- 审计日志；
- 模型与 Prompt 版本管理；
- 质量监控与异常处理。

企业级部署不仅是增加用户数量，还必须验证权限隔离、数据安全、系统稳定性和责任边界。

## 5. 长期商业化方向

知客 ZhiKe AI 长期可探索发展为 **AI Business Employee 服务平台**，为不同企业和业务人员提供可配置、可评测、可部署的 AI 员工能力。

可能的商业模式方向包括：

- 企业订阅；
- AI 员工能力包；
- 行业解决方案；
- 企业部署与实施服务。

商业化需建立在真实用户验证、数据合规、服务稳定性和可持续交付能力之上。本路线图不设定具体价格，也不将未来商业模式作为 W2 已验证结论。

## 6. 技术演进路线

| 阶段 | 技术能力 | 用户价值 | 状态 |
|---|---|---|---|
| W2 | Workflow Agent：链式 Skills、结构化输出、事实边界、内存 Mock 日报 | 验证从客户输入到业务行动的核心闭环 | 当前 Prototype 范围，需以 Demo 和评测验收 |
| W3 | Memory + Multi-client Agent：真实多客户数据、历史记录、连续记忆 | 持续辅助业务员管理和跟进多个客户 | 下一阶段规划 |
| W4 | Enterprise Agent Platform：外部连接、权限、安全、知识库和部署能力 | 支持企业业务流程中的可控应用 | 长期产品方向 |

## 7. 产品价值演进

### 第一阶段：信息整理

AI 帮助业务员从零散记录中提取客户信息，生成结构化客户档案，降低重复整理成本。

### 第二阶段：业务辅助

AI 结合客户历史和业务规则，辅助分析客户、判断机会、制定跟进计划，并持续更新多个客户的行动优先级。

### 第三阶段：受控业务执行

AI 在权限、规则、审计和人工确认机制下参与企业业务流程，承担标准化的信息处理和建议生成任务。

产品价值演进可概括为：

**信息整理 → 业务辅助 → 受控业务执行**

“业务执行”不等于完全自主决策。涉及客户发送、报价、合同、数据授权和高风险操作时，应保留明确的人工审批与责任边界。

## 8. 总结

知客 ZhiKe AI 将从验证业务处理流程的 W2 Prototype，逐步探索成为面向业务人员和企业组织的 AI Business Employee 平台。其技术演进路径是 Workflow、Memory、External Integration 和 Enterprise Deployment：W2 验证结构化核心闭环，W3 规划真实多客户管理与连续记忆，W4 探索外部系统连接和企业级部署。所有未来能力均需经过实际开发、合规检查和评测后才能视为可交付功能。
