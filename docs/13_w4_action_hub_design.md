# 知客 ZhiKe AI：低输入业务行动中枢设计

## 1. 设计目标

知客不要求业务员在每次沟通后重新整理完整聊天记录。W4 将高频入口调整为“业务快记”：业务员完成电话、会议或微信沟通后，仅记录一句关键进展，系统结合已有客户上下文生成可确认的下一步行动。

目标是减少录入与整理成本，而不是增加一层 CRM 填表工作。

## 2. 核心流程

业务员完成业务动作 → 输入一句业务进展 → 7 Skills 结合必要上下文分析 → 输出行动草案、风险提示与客户更新 → 业务员确认或忽略 → 确认后创建待办 → 后续人工反馈更新 KPI。

其中：

- AI 建议不自动发送给客户；
- AI 建议不自动计入 KPI；
- 只有“确认并创建待办”会写入任务；
- 只有业务员确认的跟进结果会写入 KPI。

## 3. 输入边界

推荐输入：例如“李总确认下周三可以演示，但希望先看数据安全说明；预算仍待确认。”

首次建立客户档案、需要完整复盘时，仍可使用“深度分析”粘贴较完整的沟通记录。系统会提示用户不要输入身份证号、银行卡号、完整联系方式、合同密钥等敏感信息；分析内容会发送至当前配置的模型服务。

## 4. 行动草案

每次业务快记生成一项“待人工确认”的行动草案，展示：客户、建议行动、风险提示与生成原因。用户可：

1. 确认并创建待办；
2. 暂不创建；
3. 进入客户洞察查看完整分析，再决定如何处理。

## 5. 可评测标准

| 指标 | 验证方法 | 合格标准 |
|---|---|---|
| 输入负担 | 用一句业务进展完成一次操作 | 无需必填 CRM 字段或完整聊天记录 |
| 行动可执行性 | 检查行动草案是否包含对象与动作 | 业务员可确认、修改或忽略 |
| 人工控制 | 检查确认前任务与 KPI 状态 | 未确认时不创建任务、不计 KPI |
| 可追溯性 | 查看客户、任务与反馈记录 | 行动来源可标明为 AI 建议或人工创建 |
| 数据隔离 | 使用两个账号分别查看数据 | 客户、任务与反馈仅对所属账号可见 |

## 6. 后续方向

后续可在取得用户授权、符合平台与第三方系统规则的前提下，接入语音转写、图片/OCR、企业微信、邮件和日历等低打扰信息源。本阶段不宣称自动读取私人微信或自动发送外部消息。
