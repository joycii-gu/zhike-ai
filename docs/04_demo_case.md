# 知客 ZhiKe AI：Demo Case 示例案例

> 项目副标题：面向业务员的 AI 业务处理智能体  
> 适用阶段：S3 全球青年培育赛 · W2 复赛 · X创新赛道  
> 文档定位：W2 Demo 输入、预期输出与评测样例

## 1. 文档目的

本文件展示知客 ZhiKe AI 在 W2 网页 Demo 中的典型输入与预期输出，帮助评委快速理解：

- 用户向 Demo 输入什么内容；
- 系统如何将非结构化信息转化为结构化结果；
- 输出结果包含哪些业务模块；
- 如何体现从“客户信息输入”到“业务行动生成”的完整闭环；
- 如何通过内存 Mock 今日客户演示跨客户业务日报。

本文案例仅用于 W2 Demo 演示、开发验收和评测，不代表真实客户数据。预期输出用于定义合理的结构和内容边界；实际 Demo 输出应在运行后另行记录，不能将本文预期结果直接作为已达成的评测结果。

## 2. Demo 输出结构说明

每个案例的预期输出统一包含以下 6 个模块：

1. **客户档案：** 将零散客户信息整理为统一字段，并标注事实、推测和未知项。
2. **客户需求分析：** 识别显性需求、潜在痛点、决策阶段、成交阻碍和待确认问题。
3. **业务机会判断：** 基于证据审慎判断跟进优先级，同时列出有利信号和不确定因素。
4. **跟进建议：** 将分析结果转化为包含动作、对象、时点和目标的下一步行动。
5. **沟通话术：** 为业务员生成可编辑、需人工确认的沟通参考。
6. **业务日报：** 联合当前客户与 Mock 今日客户，汇总优先级、待办、风险和明日计划。

## 3. Mock 今日客户说明

W2 Demo 后端内存中预置 2—3 个 Mock 今日客户，用于验证业务日报的跨客户汇总能力。本文件固定使用以下 2 个 Mock 客户。Mock 数据只用于演示，不写入数据库，不代表真实历史数据；页面刷新或服务重启后恢复初始状态。

### Mock-A：王经理

- **行业：** 企业软件
- **当前阶段：** 方案比较阶段
- **需求：** 希望比较 AI 客户跟进工具与现有 CRM 的差异
- **关注点：** 数据安全、部署成本、团队培训
- **机会等级：** 中高
- **待办：** 补充方案对比材料，确认决策流程
- **风险：** 客户对数据安全要求较高，需明确权限与数据处理边界

### Mock-B：陈老师

- **行业：** 职业教育
- **当前阶段：** 初步咨询阶段
- **需求：** 希望提升课程顾问对学员咨询的跟进效率
- **关注点：** 话术质量、使用门槛、是否适合新人顾问
- **机会等级：** 中
- **待办：** 发送需求确认问题清单
- **风险：** 需求较宽泛，尚未明确预算与试用范围

## 4. 案例一：企业培训客户

### 4.1 用户输入

> 李总，做企业培训，最近想了解 AI 员工如何帮助销售团队做客户跟进。之前看过我们的 HermesAgent 安装服务，对 AI 业务助理感兴趣，但还没有明确预算，希望下周约一次线上沟通。他比较关心部署难度、价格、实际效果，以及业务员是否真的会用。

### 4.2 预期输出

#### 1）客户档案

| 字段 | 内容 | 信息属性 |
|---|---|---|
| 客户称谓 | 李总 | 事实 |
| 所属行业 | 企业培训 | 事实 |
| 客户角色 | 可能为企业负责人或业务决策相关人员，具体权限待确认 | 推测 |
| 核心需求 | 了解 AI 员工如何辅助销售团队进行客户跟进 | 事实 |
| 已知兴趣 | 对 AI 业务助理感兴趣；曾了解 HermesAgent 安装服务 | 事实 |
| 主要关注点 | 部署难度、价格、实际效果、业务员采用意愿 | 事实 |
| 预算 | 未明确 | 未知/待确认 |
| 当前阶段 | 初步了解与方案探索阶段 | 推测 |
| 时间计划 | 希望下周进行线上沟通 | 事实 |
| 待确认信息 | 团队规模、现用工具、决策权限、预算范围、试用范围和预期上线时间 | 未知/待确认 |

#### 2）客户需求分析

- **显性需求：** 了解 AI 员工是否能够辅助销售团队处理客户跟进工作。
- **潜在痛点：** 当前团队可能存在客户信息整理耗时、跟进执行不一致或工具采用率不足等问题；原文未明确，需在下次沟通中验证。
- **决策阶段：** 处于方案认知和可行性探索阶段，尚无证据表明已进入采购阶段。
- **关键决策因素：** 部署难度、价格、实际效果和业务员采用意愿。
- **成交阻碍：** 预算未明确；团队规模与现有流程未知；客户对部署和采用率存在顾虑。
- **待确认问题：** 当前销售团队规模和日均客户量是多少？现用什么工具？哪个跟进环节最耗时？谁参与方案决策？是否考虑小范围试用？

#### 3）业务机会判断

- **机会等级：** 中。
- **有利信号：** 已主动关注 AI 业务助理；了解过相关服务；提出明确关注点；愿意安排下一次线上沟通。
- **不确定因素：** 预算、决策权限、团队规模、实施范围和采购时点均未明确。
- **判断依据：** 客户具有明确兴趣和后续沟通意愿，但关键采购条件尚不完整，不宜判定为高意向。
- **风险提醒：** 不应在需求、预算和部署条件未确认前承诺效果或给出确定性方案。

#### 4）跟进建议

1. **动作：** 发送会议时间选项；**对象：** 李总；**时点：** 1 个工作日内；**目标：** 确认下周线上沟通时间。
2. **动作：** 准备一页式核心闭环演示；**对象：** 李总及可能参会人员；**时点：** 会前 1 天；**目标：** 直观说明产品如何处理客户跟进任务。
3. **动作：** 准备部署步骤、使用门槛和试点评测指标；**对象：** 李总；**时点：** 会前；**目标：** 回应部署与实际效果关注，但不作未经验证的效果承诺。
4. **动作：** 询问团队规模、现用工具和主要耗时环节；**对象：** 李总；**时点：** 线上会议前半段；**目标：** 验证真实业务痛点。
5. **动作：** 确认决策参与者、预算范围和试用意愿；**对象：** 李总；**时点：** 需求初步明确后；**目标：** 判断是否进入试点方案讨论。

#### 5）沟通话术

> 李总您好，您上次提到比较关注 AI 业务助理的部署难度、价格、实际效果，以及业务员是否愿意使用。我们可以在下周安排一次线上沟通，我会结合一个客户跟进案例，演示从信息整理、需求分析到跟进建议和日报生成的完整流程，也想进一步了解您团队目前的跟进方式。您下周二或周四哪个时间段比较方便？

#### 6）业务日报

- **数据组成：** 当前新输入客户李总 + Mock-A 王经理 + Mock-B 陈老师。
- **今日新增/更新客户：** 李总进入方案探索；王经理处于方案比较；陈老师处于初步咨询。
- **高优先级排序：** 1）王经理，中高机会，需补充方案对比并确认决策流程；2）李总，中等机会，需确认会议及真实需求；3）陈老师，中等机会但需求较宽泛，需先完成资格确认。
- **跨客户待办：** 向王经理补充方案对比材料；1 个工作日内向李总发送会议时间；向陈老师发送需求确认问题清单。
- **全局风险提醒：** 王经理关注数据安全；李总预算与决策权限未知；陈老师预算和试用范围未知。三位客户均不适合在条件未确认前作效果或交付承诺。
- **明日计划：** 优先推进王经理的方案比较事项；完成李总会议邀约和演示准备；收集陈老师的团队与需求信息。
- **数据范围说明：** 日报仅基于当前案例与内存 Mock 数据生成，不写入数据库，不代表真实历史记录或真实多客户管理。

## 5. 案例二：课程顾问客户

### 5.1 用户输入

> 周校长经营一家职业技能培训机构，想了解 AI 能否帮助课程顾问整理学员微信咨询、判断报名意向并生成后续沟通话术。机构目前有 6 名课程顾问，新人较多，周校长担心 AI 话术太生硬，也担心顾问不会使用。预算暂时没有确定，希望本周五先看一次线上演示，再决定是否安排小范围试用。机构目前每天收到多少条咨询、使用什么表格或系统记录，尚未说明。

### 5.2 预期输出

#### 1）客户档案

| 字段 | 内容 | 信息属性 |
|---|---|---|
| 客户称谓 | 周校长 | 事实 |
| 所属行业 | 职业技能培训 | 事实 |
| 客户角色 | 机构经营者，是否为最终采购决策人待确认 | 事实 + 未知 |
| 核心需求 | 整理学员咨询、判断报名意向、生成跟进话术 | 事实 |
| 已知兴趣 | 愿意观看线上演示并考虑小范围试用 | 事实 |
| 主要关注点 | 话术自然度、新人使用门槛、顾问采用情况 | 事实 |
| 预算 | 未确定 | 未知/待确认 |
| 当前阶段 | 演示评估前的需求探索阶段 | 推测 |
| 时间计划 | 本周五观看线上演示 | 事实 |
| 待确认信息 | 日均咨询量、现用记录工具、决策参与者、预算范围、试用人数与周期 | 未知/待确认 |

#### 2）客户需求分析

- **显性需求：** 用 AI 辅助课程顾问整理学员咨询、判断意向并生成跟进话术。
- **潜在痛点：** 新人顾问可能缺乏稳定的信息归纳和沟通方法；该点基于“新人较多”的推断，需通过实际流程验证。
- **决策阶段：** 准备观看演示，尚未进入明确预算或采购阶段。
- **关键决策因素：** 话术是否自然、顾问是否容易使用、是否适合小范围试用。
- **成交阻碍：** 预算未知；咨询规模和现用流程未知；对 AI 话术质量和采用率有顾虑。
- **待确认问题：** 日均咨询量是多少？目前如何记录和分配线索？新人最常遗漏什么？计划由多少人试用、试用多久？谁参与采购决策？

#### 3）业务机会判断

- **机会等级：** 中高。
- **有利信号：** 使用场景明确；团队规模已知；存在新人培训诉求；已提出具体演示时间；愿意考虑小范围试用。
- **不确定因素：** 预算、咨询量、现用工具、试用范围和最终决策流程未明确。
- **判断依据：** 客户问题与产品能力匹配，且有明确下一步，但采购条件仍需确认，因此不判定为高机会。
- **风险提醒：** 需要用实际样例验证话术质量和新人可用性，不能仅凭演示承诺采用效果。

#### 4）跟进建议

1. **动作：** 确认线上演示参会人和时间；**对象：** 周校长；**时点：** 本周四前；**目标：** 保证演示场景与参会角色匹配。
2. **动作：** 准备课程咨询示例；**对象：** 周校长及课程顾问；**时点：** 演示前；**目标：** 展示咨询整理、意向判断和话术生成闭环。
3. **动作：** 询问日均咨询量和现用记录方式；**对象：** 周校长；**时点：** 演示开始前；**目标：** 确认真实工作量与主要痛点。
4. **动作：** 展示事实/推断/未知标签；**对象：** 课程顾问；**时点：** 演示中；**目标：** 说明系统如何避免把未知预算或意向写成事实。
5. **动作：** 讨论小范围试用指标；**对象：** 周校长；**时点：** 演示反馈积极后；**目标：** 明确试用人数、周期、话术可用率和操作完成率。

#### 5）沟通话术

> 周校长您好，本周五的演示我会用一个课程咨询案例，完整展示学员记录整理、意向分析、跟进建议和话术生成，并重点说明新人顾问如何使用、话术如何避免生硬。为了让演示更贴近您团队，方便的话请提前告诉我目前大致的日均咨询量和记录方式。我们按原计划周五线上沟通可以吗？

#### 6）业务日报

- **数据组成：** 当前新输入客户周校长 + Mock-A 王经理 + Mock-B 陈老师。
- **今日新增/更新客户：** 周校长确认本周五演示意向；王经理处于方案比较；陈老师处于初步咨询。
- **高优先级排序：** 1）周校长，中高机会且已有明确演示时点；2）王经理，中高机会，需推进安全与方案比较；3）陈老师，中等机会，需进一步确认需求范围。
- **跨客户待办：** 为周校长准备课程咨询演示并确认参会人；向王经理补充方案对比与数据边界材料；向陈老师发送需求确认清单。
- **全局风险提醒：** 周校长和陈老师均未明确预算；王经理对数据安全要求较高；所有话术和效果均需通过实际案例验证。
- **明日计划：** 完成周校长的演示材料；推进王经理的决策流程确认；跟进陈老师的预算与试用范围。
- **数据范围说明：** 日报仅基于当前案例与内存 Mock 数据生成，不进行数据库保存或跨会话持久化。

## 6. 案例三：企业服务客户

### 6.1 用户输入

> 赵总负责一家为小微企业提供工商、财税和政策咨询服务的公司。团队有 4 名业务员，客户需求经常散落在电话纪要和个人备注里。赵总希望 AI 能帮助整理企业客户需求、提炼方案沟通重点并生成跟进计划。目前处于内部了解阶段，准备下周让两名业务员参加产品演示。他关注数据保密、输出是否准确和员工使用成本；公司现有客户记录方式、预算以及是否允许使用真实客户材料做测试还没有确定。

### 6.2 预期输出

#### 1）客户档案

| 字段 | 内容 | 信息属性 |
|---|---|---|
| 客户称谓 | 赵总 | 事实 |
| 公司或行业背景 | 小微企业工商、财税和政策咨询服务 | 事实 |
| 客户角色 | 公司负责人；具体采购流程待确认 | 事实 + 未知 |
| 核心需求 | 整理企业客户需求、提炼方案沟通重点、生成跟进计划 | 事实 |
| 已知兴趣 | 准备安排两名业务员参加产品演示 | 事实 |
| 主要关注点 | 数据保密、输出准确性、员工使用成本 | 事实 |
| 预算 | 未明确 | 未知/待确认 |
| 当前阶段 | 内部了解阶段 | 事实 |
| 时间计划 | 下周安排产品演示 | 事实 |
| 待确认信息 | 现有记录方式、预算、测试数据范围、决策流程、合规要求 | 未知/待确认 |

#### 2）客户需求分析

- **显性需求：** 将散落在电话纪要和个人备注中的企业客户信息整理为需求、沟通重点和跟进计划。
- **潜在痛点：** 团队可能存在信息口径不一致、交接困难和跟进遗漏；这些属于基于输入的合理推断，需向业务员验证。
- **决策阶段：** 内部了解和演示准备阶段。
- **关键决策因素：** 数据保密、输出准确性、员工使用成本和测试材料合规性。
- **成交阻碍：** 数据使用边界未确定；预算未知；现用流程和采购决策方式不清楚。
- **待确认问题：** 当前如何记录客户？哪些信息最容易遗漏？能否使用脱敏案例测试？谁负责安全与采购确认？希望先验证哪个服务场景？

#### 3）业务机会判断

- **机会等级：** 中。
- **有利信号：** 问题场景具体；团队规模明确；计划安排实际业务员参与演示；关注点清晰。
- **不确定因素：** 预算、现用工具、测试数据权限、采购流程和上线时点未知。
- **判断依据：** 客户具有明确业务问题与演示意愿，但数据合规和采购条件尚未确认，暂不宜判为中高或高机会。
- **风险提醒：** 不应要求客户直接上传含敏感信息的真实材料；演示应优先使用脱敏或虚构案例。

#### 4）跟进建议

1. **动作：** 确认演示时间和两名业务员的职责；**对象：** 赵总；**时点：** 2 个工作日内；**目标：** 选择贴近真实工作的演示场景。
2. **动作：** 提供脱敏输入模板；**对象：** 赵总及参演业务员；**时点：** 演示前；**目标：** 避免在 Demo 中使用敏感客户信息。
3. **动作：** 询问现有记录与交接方式；**对象：** 两名业务员；**时点：** 演示前半段；**目标：** 验证信息分散和跟进遗漏问题。
4. **动作：** 展示证据回溯和未知项标注；**对象：** 赵总；**时点：** 演示中；**目标：** 回应输出准确性与事实边界关注。
5. **动作：** 确认数据、安全、预算和试用条件；**对象：** 赵总及相关负责人；**时点：** 演示反馈后；**目标：** 判断是否具备后续小范围验证条件。

#### 5）沟通话术

> 赵总您好，下周演示我们可以围绕“电话纪要和个人备注如何转成客户需求、沟通重点和跟进计划”来展开，并重点展示事实依据、未知项标注和数据范围说明。为保护客户信息，建议先使用脱敏或虚构案例。您方便确认一下参演的两名业务员主要负责哪些服务场景，以及下周哪个时间段合适吗？

#### 6）业务日报

- **数据组成：** 当前新输入客户赵总 + Mock-A 王经理 + Mock-B 陈老师。
- **今日新增/更新客户：** 赵总进入演示准备；王经理处于方案比较；陈老师处于初步咨询。
- **高优先级排序：** 1）王经理，中高机会，需推进安全与决策流程；2）赵总，中等机会，需先确认数据边界和演示场景；3）陈老师，中等机会，需明确需求与预算。
- **跨客户待办：** 为王经理补充数据安全和方案对比材料；向赵总提供脱敏模板并确认演示人员；向陈老师发送需求确认清单。
- **全局风险提醒：** 王经理和赵总均高度关注数据安全；赵总和陈老师预算未知；演示材料必须避免未经授权的真实客户信息。
- **明日计划：** 完成王经理安全问题清单；确认赵总演示场景和人员；收集陈老师的试用范围信息。
- **数据范围说明：** 日报仅基于当前案例与内存 Mock 数据生成，不代表真实经营数据，不提供持久化客户管理。

## 7. 三个案例覆盖能力说明

| 案例 | 行业/角色 | 主要验证能力 |
|---|---|---|
| 案例一 | 企业培训 / 可能的企业负责人或决策相关人员 | 从简短备注提取信息；标注未知预算与角色；审慎判断机会；生成会议跟进和跨客户日报 |
| 案例二 | 职业培训 / 机构经营者与课程顾问团队 | 分析新人顾问使用场景；评估话术质量和采用门槛；设计演示与试用动作；进行跨客户排序 |
| 案例三 | 小微企业服务 / 公司负责人 | 处理复杂企业服务需求；识别数据保密风险；生成脱敏演示建议；汇总跨客户安全风险 |

三个案例共同覆盖信息提取、结构化客户档案、需求分析、机会判断、跟进建议、话术生成和跨客户业务日报。

## 8. 与评测标准的关系

| 评测指标 | 可在案例中观察的内容 |
|---|---|
| 信息提取完整度 | 姓名、行业、需求、关注点、预算和时点是否与输入一致，是否存在遗漏或臆造 |
| 客户档案结构化程度 | 字段是否统一，事实、推测和未知是否清晰，信息是否归类正确 |
| 需求分析准确性 | 显性需求是否有原文依据，潜在痛点是否标注推断，待确认问题是否合理 |
| 业务机会判断合理性 | 机会等级是否同时考虑有利信号、不确定因素和风险 |
| 跟进建议可执行性 | 建议是否包含动作、对象、时点和目标，并符合当前阶段 |
| 沟通话术可用性 | 话术是否自然、针对、有下一步，且无虚构事实或效果承诺 |
| 业务日报完整度 | 当前客户和两个 Mock 客户是否均被纳入，排序、待办和风险是否可回溯 |
| 用户操作简易度 | 测试者能否通过选择案例、一次点击完成报告生成并理解结果 |

本文提供预期输出结构，正式评分应使用 Demo 的实际运行输出，并按照 [`docs/05_evaluation.md`](05_evaluation.md) 记录得分、问题和改进项。

## 9. 使用说明

评委或测试者可按以下步骤使用案例：

1. 打开网页 Demo；
2. 选择示例案例，或复制本文件中的用户输入；
3. 点击“一键生成业务处理报告”；
4. 对照本文档的预期输出结构，检查模块完整性、事实边界和行动可执行性；
5. 根据 [`docs/05_evaluation.md`](05_evaluation.md) 中的标准进行评分；
6. 保存实际输入、实际输出、模型版本、评分与问题记录。

若网页 Demo 或评测文件尚未完成，应将本文件作为开发和验收样例，而不能把预期输出当作已验证结果。

## 10. 边界说明

- 本文案例均为演示案例，不代表真实客户数据；
- Mock 客户不是实际客户，也不代表真实历史记录；
- 输出话术仅供业务员参考，发送前需要人工确认；
- 业务机会判断是辅助判断，不替代业务员最终决策；
- W2 不包含真实 CRM、微信、数据库、日历或 OCR 接入，也不提供跨会话持久化；
- 真实多客户管理、历史跟进记录和 Agent 记忆计划在 W3 阶段验证；
- 外部系统接入属于 W4 规划，不能作为 W2 已实现能力宣传。

## 11. 总结

本 Demo Case 文档通过企业培训、课程顾问和企业服务三个不同行业与角色的案例，展示知客 ZhiKe AI 如何把非结构化客户信息转化为结构化档案、需求分析、业务机会判断、跟进建议、沟通话术和跨客户业务日报。它用于验证 W2 Prototype 的核心闭环、事实边界和输出结构，并为后续实际评测提供样例基础。
