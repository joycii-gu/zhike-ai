# 客户信息解析 + 客户档案生成 Skill

## 定位

本 Skill 是知客 ZhiKe AI Workflow 的入口环节，分两个内部步骤运行：

1. **信息解析（FR1）**：从原始文本中抽取客户身份、行业、角色、需求、关注点、预算信号、时间计划、当前阶段，并保留可回溯的原文证据。
2. **档案生成（FR2）**：将解析结果去重、归类，合并为业务员可以在几秒内看懂的统一客户档案。

两步串联执行，不要跳过第 1 步直接输出档案 —— 第 1 步的"事实/推断/未知"标注和证据摘录，是第 2 步档案可信度的来源，也是后续所有 Skill 判断的证据链起点。

## 核心规则（不可违反）

- **只提取原文中出现或可合理推断的信息**；不得编造原文没有的具体数字、承诺、时间点或事实。
- **每个字段值必须带标注前缀**：
  - `【事实】` — 原文明确出现；
  - `【推断】` — 基于上下文合理推测，需业务员人工确认；
  - `【未知】` — 原文未出现或无法判断，不要试图强行补全。
  数组类字段（需求、关注点等）中的每一项都需单独加前缀，不能整体只标一次。
- **不将原文没有的信息写成确定事实**。宁可标"未知/待确认"，也不要猜测性地写成陈述句。
- 档案阶段**不新增**解析阶段没有的信息，只做合并、去重、归类；如发现字段冲突（例如两处提到不同预算），保留两者并在"待确认事项"中提示。

## 输入

- 必需：客户沟通原始文本（聊天记录 / 电话纪要 / 会议备注 / 名片信息 / 表单记录等，纯文本）。
- 可选：如有多轮/多渠道记录，可拼接输入，但需在证据摘录中标明来源片段。

## 处理流程

### 步骤 1：信息解析

按以下 JSON 结构输出（字段值均按上文规则加标注前缀）：

```json
{
  "客户称谓": "",
  "行业": "",
  "角色": "",
  "需求": ["每项都带标注前缀，不超过4项"],
  "关注点": ["每项都带标注前缀，不超过4项"],
  "预算信号": "带标注前缀",
  "时间计划": "带标注前缀",
  "当前阶段": "了解/比较/试用/采购决策/未知，带标注前缀",
  "待确认字段": ["列出需要业务员进一步确认的关键信息点"],
  "证据摘录": ["1-3条支撑判断的原文关键片段，需简短"]
}
```

### 步骤 2：档案生成

以步骤 1 的 JSON 为输入，合并、去重、归类，输出：

```json
{
  "基本信息": { "称谓": "", "行业": "", "角色": "" },
  "核心需求": ["..."],
  "关注点": ["..."],
  "决策阶段": "",
  "时间计划": "",
  "待确认事项": ["..."]
}
```

两步均只输出合法 JSON，不加解释文字、不加 Markdown 代码块标记。

## 验收标准（对应 Specs §7.2 / §7.3）

| 检查项 | 合格标准 |
|---|---|
| 信息提取完整度 | 关键字段（称谓/行业/角色/需求/关注点/阶段）提取完整度 ≥ 80%；不出现关键事实臆造；重要字段可回溯到原文 |
| 事实/推断/未知区分 | 每个字段值均带标注前缀，且标注与原文实际情况一致 |
| 档案结构化程度 | 字段覆盖率 ≥ 90%；分类清晰（基本信息/核心需求/关注点/决策阶段/时间计划/待确认事项）；业务员可在短时间内理解客户情况 |
| 无字段错位 | 不出现将需求写进关注点、将推断写成事实等错位问题 |

## 示例

**输入**：
```
客户：王磊，某中型制造企业的信息化负责人。上周展会上加了微信，今天在微信上聊：
王磊：你好，我们工厂想上一套生产管理系统，之前一直用Excel记，太乱了。你们这个系统能对接我们现有的ERP吗？
业务员：可以的，我们支持主流ERP接口对接。您这边大概多少人用？
王磊：车间加办公室大概80人吧。对了这个多少钱，我们老板比较关心价格，但更看重能不能真的落地用起来，之前上过一套系统最后没人用。
业务员：了解，价格是按用户数阶梯计费的，我发个报价给您参考。
王磊：行，你先发资料我看看，我们内部大概下个月要开会讨论要不要上，如果合适的话Q3想落地。不过我不是最终拍板的，得我们总经理点头。
```

**步骤1输出（节选）**：
```json
{
  "客户称谓": "【事实】王磊",
  "行业": "【事实】制造业",
  "角色": "【事实】信息化负责人（非最终决策人）",
  "需求": ["【事实】生产管理系统替代Excel记录", "【事实】需对接现有ERP系统"],
  "关注点": ["【事实】价格（老板关心）", "【推断】系统落地使用率，担心重蹈上次失败经历"],
  "预算信号": "【未知】未提及具体预算范围",
  "时间计划": "【事实】下月内部开会讨论，若通过Q3落地",
  "当前阶段": "【事实】比较/评估阶段",
  "待确认字段": ["具体预算范围", "总经理的决策倾向和关注点"],
  "证据摘录": ["我们工厂想上一套生产管理系统，之前一直用Excel记，太乱了", "我不是最终拍板的，得我们总经理点头"]
}
```

**步骤2输出（节选）**：
```json
{
  "基本信息": { "称谓": "王磊", "行业": "制造业", "角色": "信息化负责人（非最终决策人）" },
  "核心需求": ["生产管理系统替代Excel", "需对接现有ERP"],
  "关注点": ["价格", "系统实际落地使用率"],
  "决策阶段": "比较/评估阶段，需总经理最终拍板",
  "时间计划": "下月内部开会，若通过则Q3落地",
  "待确认事项": ["具体预算范围", "总经理的决策倾向", "现有ERP具体型号/接口情况"]
}
```
