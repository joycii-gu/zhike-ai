# 客户信息解析 Skill

## 定位

本 Skill 对应 W3 Workflow 的 Skill 1。它不直接给出成交结论或长篇建议，而是把聊天记录、电话纪要、会议备注和业务员手工记录转为后续 Skills 可使用的最小结构化上下文。其价值是为客户档案、需求分析和机会判断保留明确证据，减少模型把未知信息写成事实的风险。

## 输入

- 必需：一段原始客户记录。
- 可选：业务员补充的客户称谓、沟通渠道和计划跟进时间。

## 输出契约

```json
{
  "facts": {
    "customer_name": "原文明确出现的称谓；未出现则未知",
    "industry": "行业或未知",
    "role": "角色或未知",
    "needs": ["显性需求"],
    "concerns": ["明确关注点"],
    "budget_signal": "预算信号或未知",
    "time_signal": "时间计划或未知",
    "stage_signal": "当前阶段线索或未知"
  },
  "inferences": ["必须说明推断依据，不能替代事实"],
  "unknowns": ["需要后续确认的关键信息"],
  "evidence": ["1—3 条原文关键片段"]
}
```

## 核心规则

- 未出现的信息必须写入 `unknowns`，不得补写具体预算、决策人或采购时间。
- 推断只能放入 `inferences`，并以原文线索为依据。
- `evidence` 必须来自用户输入，方便后续 Skill 和人工核查。
- 输出只包含结构化 JSON，不生成销售承诺、报价或成交概率。

## 合格标准

| 检查项 | 合格标准 |
|---|---|
| 信息完整度 | 称谓、行业、角色、需求、关注点、阶段等已出现关键信息提取完整度不低于 80% |
| 可追溯性 | 关键判断至少保留一条相应原文证据 |
| 审慎性 | 不把原文未出现的预算、权限或时点写成事实 |
| 可串联性 | 输出可直接作为客户档案生成 Skill 的输入 |

## 与后续 Skill 的关系

`customer_info_parse` 的输出会传递给 `customer_profile`。客户档案生成仅负责合并、去重与展示，不应重新编造本步骤未确认的字段。
