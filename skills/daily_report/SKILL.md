# 业务日报 Skill

## 定位

前六个 Skill 都是围绕单一客户展开的，本 Skill 是唯一的跨客户聚合环节，模拟业务员每天下班前做的复盘："今天都处理了谁、谁最优先、有什么没做完、有什么风险、明天先做什么"。

## 核心规则（不可违反）

1. **只能使用输入数组范围内的客户**，不得编造范围外的客户，也不得把同一个客户的信息拆成两个客户重复计入。
2. **优先级排序需给出具体客户名称的顺序**（而不是抽象描述），排序依据可参考各客户的商机等级和风险紧急度。
3. **待办事项必须能对应到具体客户**，不能出现"跟进客户"这种不知道对应谁的模糊待办。
4. **风险提醒必须可回溯到客户信息**，即每条风险都要能说出是哪个客户、什么风险，不能凭空生成不属于任何客户的风险。
5. **明日计划应具体到可执行的动作层面**，而不是"继续跟进所有客户"这类空话。

## 输入

当日已处理客户的结构化摘要数组，每个元素通常来自单个客户跑完前几个 Skill 后的摘要（客户名、行业、商机等级、待办、风险等），例如：

```json
[
  {
    "客户": "",
    "行业": "",
    "商机等级": "",
    "待办": "",
    "待办对象": "",
    "风险": ["..."]
  }
]
```

> 注：数组里客户数量、字段完整度取决于当天实际处理了几个客户；本 Skill 不要求每个客户字段都齐全，缺失字段按"未知"处理，不臆造。

## 输出结构

只输出合法 JSON，不加解释文字、不加 Markdown 代码块标记：

```json
{
  "今日客户情况": [{ "客户": "", "要点": "" }],
  "优先级排序": ["客户名称，按优先级从高到低"],
  "待办事项": [{ "客户": "", "待办": "" }],
  "风险提醒": [{ "客户": "", "风险": "" }],
  "明日计划": ["..."]
}
```

## 验收标准（对应 Specs §7.8）

| 检查项 | 合格标准 |
|---|---|
| 覆盖范围 | 日报覆盖输入范围内全部客户，不遗漏、不重复 |
| 不越界 | 不写入输入集合之外的客户 |
| 待办可追溯 | 每条待办都能对应到具体客户 |
| 风险可回溯 | 每条风险提醒都能追溯到对应客户的信息 |
| 明日计划具体 | 明日计划是具体动作，不是空泛套话 |

## 示例

**输入**：
```json
[
  {
    "客户": "王磊", "行业": "制造业", "商机等级": "中",
    "待办": "发送产品报价单及ERP对接方案说明，附同行业案例", "待办对象": "王磊",
    "风险": ["王磊不是最终决策人", "此前系统落地失败带来内部信任成本"]
  },
  {
    "客户": "李女士", "行业": "K12课外辅导", "商机等级": "中高",
    "待办": "根据周末时间安排试听课", "待办对象": "李女士",
    "风险": ["仍在对比另外两家机构，尚未确定"]
  }
]
```

**输出**：
```json
{
  "今日客户情况": [
    { "客户": "王磊", "要点": "制造业客户，需求明确（替代Excel+对接ERP），商机等级中，关键卡点是需通过总经理审批" },
    { "客户": "李女士", "要点": "K12课外辅导意向家长，商机等级中高，正在对比另外两家机构，需尽快约试听锁定意向" }
  ],
  "优先级排序": ["李女士", "王磊"],
  "待办事项": [
    { "客户": "李女士", "待办": "根据周末时间安排试听课，抢在对比结果出来前建立信任" },
    { "客户": "王磊", "待办": "发送产品报价单及ERP对接方案说明，附同行业案例" }
  ],
  "风险提醒": [
    { "客户": "李女士", "风险": "客户仍在对比另外两家机构，存在流失风险，需加快响应速度" },
    { "客户": "王磊", "风险": "最终决策权在总经理，且此前系统落地失败可能带来内部推进阻力" }
  ],
  "明日计划": [
    "确认李女士周末试听课具体时段并提前告知任课老师客户的顾虑点（孩子对数学有抵触情绪）",
    "跟进王磊是否已将材料转发给总经理，询问总经理端是否有反馈"
  ]
}
```
