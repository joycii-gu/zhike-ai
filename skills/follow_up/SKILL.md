# 跟进建议 Skill

## 定位

前面三个 Skill 完成的是"理解客户"，本 Skill 完成的是"转化为行动"——这是知客 ZhiKe AI 区别于普通信息整理工具的关键交付物。产出必须是业务员拿到手就能执行的具体动作，而不是"继续跟进"这种正确但没用的空话。

## 核心规则（不可违反）

1. **每条建议必须同时包含六个要素**：动作、对象、时点建议、沟通目标、准备材料、优先级（高/中/低）。缺少任意一项都视为不合格。
2. **建议必须符合客户当前所处阶段**（来自客户档案的"决策阶段"）。例如客户仍处于"比较/评估阶段"且核心信息未确认时，不能直接建议"发送合同"或"约定签约时间"，应先建议确认关键信息或提供决策支持材料。
3. **不跳过需求确认直接推进成交**。如果 need_analysis 中存在"待确认问题"，通常应有至少一条建议围绕确认这些问题展开，而不是绕过去直接推销。
4. **动作必须具体可执行**，避免"保持联系"、"继续跟进"、"多沟通"等空泛表达——动作里要说清楚做什么、给谁、说什么。
5. 建议数量控制在 2-4 条，按优先级排列，避免堆砌待办让业务员无从下手。

## 输入

- 必需：`customer_profile` 输出的客户档案 JSON、`need_analysis` 输出的需求分析 JSON、`opportunity_judgement` 输出的商机判断 JSON。

## 输出结构

只输出一个合法 JSON 对象，不加解释文字、不加 Markdown 代码块标记。为与运行时统一，跟进建议数组必须放在 `output` 字段中：

```json
{
  "output": [
    {
    "动作": "",
    "对象": "",
    "时点建议": "",
    "沟通目标": "",
    "准备材料": "",
    "优先级": "高/中/低"
    }
  ]
}
```

## 验收标准（对应 Specs §7.6）

| 检查项 | 合格标准 |
|---|---|
| 六要素完整 | 每条建议都包含动作/对象/时点/目标/材料/优先级 |
| 可执行性 | 至少 80% 的建议经评测者判断为可直接执行，而非空泛表达 |
| 阶段一致性 | 建议与客户当前决策阶段一致，不跳阶段推进成交 |
| 优先级合理 | 优先级排序体现出对成交推进最关键的动作排在前面 |

## 示例

**输入（前三个 Skill 的输出摘要）**：
```json
{
  "客户档案": {
    "基本信息": { "称谓": "王磊", "行业": "制造业", "角色": "信息化负责人（非最终决策人）" },
    "决策阶段": "比较/评估阶段，需总经理最终拍板",
    "时间计划": "下月内部开会，若通过则Q3落地"
  },
  "需求分析": {
    "待确认问题": ["总经理最关注价格、效果还是实施周期？", "上次系统失败具体卡在哪个环节？"]
  },
  "商机判断": { "商机等级": "中", "风险因素": ["王磊不是最终决策人", "此前系统落地失败带来内部信任成本"] }
}
```

**输出**：
```json
[
  {
    "动作": "发送产品报价单及ERP对接方案说明，附一份同行业客户的落地案例",
    "对象": "王磊",
    "时点建议": "本周内",
    "沟通目标": "为王磊准备好可以直接转发给总经理的决策材料，降低他内部说服成本",
    "准备材料": "报价单、ERP对接技术说明、1个制造业同行案例",
    "优先级": "高"
  },
  {
    "动作": "微信询问王磊：上次系统失败具体卡在哪个环节（培训、易用性还是流程不匹配），以便在方案里针对性说明如何避免",
    "对象": "王磊",
    "时点建议": "下次沟通时，建议3天内",
    "沟通目标": "确认关键待确认问题，同时展示对客户历史顾虑的重视",
    "准备材料": "无需材料，直接沟通",
    "优先级": "高"
  },
  {
    "动作": "了解王磊是否可以安排一次与总经理的简短电话或会议，业务员可直接说明方案价值",

    "时点建议": "下月开会前，建议提前1周提出",
    "沟通目标": "争取直接触达最终决策人，降低信息在传递中失真的风险",
    "准备材料": "简明版方案介绍（适合决策层阅读）",
    "优先级": "中"
  }
]
```
